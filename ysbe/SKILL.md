# YSBE: решение карточек Яндекс Учебника

## Триггер и поведение в чате

- Пользователь пишет «начинай» → ответь ровно: «хорошо, приступаю к работе». Больше ничего.
- Во время работы НЕ пиши пояснений, рассуждений и промежуточных сообщений. Не печатай код в чат. Экономь токены.
- По окончании — один короткий отчёт: «решено N (код: X, тесты: Y)» + список пропущенных карточек с готовыми ответами для ручного ввода.

## Цикл работы

1. `status` — убедись, что открыто задание (URL вида /classroom/courses/.../assignments/.../run/). Если нет — попроси пользователя открыть задание и жди.
2. `read_task` — получи тип карточки и условие.
3. По типу:
   - `code`: реши задачу → `type_code` → `run_code` → `read_result`. Если `verdict: passed` → `submit`. Если ошибка — исправь код и повтори (максимум 2 попытки), затем запомни задачу для отчёта.
   - `test`: реши → `answer` (option или text) → `submit`.
   - `theory` или непонятный тип: при необходимости `screenshot`, прочитай файл, сразу удали его. Если карточка требует действие, которое нельзя выполнить — запомни ответ для финального отчёта.
4. `next_task` — на карточках теории кнопка «Продолжение» может появляться несколько раз подряд: вызывай `next_task` повторно, пока карточка не сменится. Если вернулось `done` — задание завершено, переходи к отчёту. Иначе повтори с шага 2.

## Скорость (обязательно!)

- Сразу после `type_code` → `run_code` → `read_result` → при `passed` сразу `submit` и `next_task`. Никаких лишних вызовов, пауз и проверок между шагами.
- Для теории — сразу `next_task`, не читай и не пересказывай условие (только `read_task` для определения типа).
- Вводный материал (критерии, шпаргалки) пропускай одним `next_task`.
- Минимум tool-вызовов на карточку: код = 6 (read_task, type_code, run_code, read_result, submit, next_task), теория = 2 (read_task, next_task).

## Правила кода (строго!)

- Python, уровень 7–8 класса: переменные, `input()`/`print()`, `if/elif/else`, `for`/`while`, списки, строки, `int`/`float`/`str`/`len`/`range`/`append`/`split`.
- ЗАПРЕЩЕНО: комментарии (`#`), функции `def` (если не требуются условием), list comprehension, lambda, f-строки, импорты (кроме явно требуемых), `enumerate`/`zip`/тернарные операторы, «умные» однострочники.
- Имена переменных простые: `a`, `b`, `n`, `s`, `x`, `spisok` или слово по смыслу.
- `print(a, b)` вместо f-строк. Ввод: `n = int(input())`.
- Код должен выглядеть так, будто его писал школьник 13–14 лет: прямолинейно, без изящества.

## Ограничения

- Никогда не используй буфер обмена и программную вставку в редактор — только `type_code` (он печатает посимвольно).
- Не изменяй файлы проекта, кроме удаления скриншотов из `server/tmp/`.
- Окно браузера не закрывать (сворачивать можно).
